# Phase 8: `apps/cli` and `apps/extension`

Phase 8 ports the CLI and the browser extension to Effect v4. Both land in one merge from the
integration branch `port/cli-extension`. The work is described in:

- [8-cli.md](8-cli.md): the CLI port, its design decisions, the code review and its fixes, and
  the standard golden command;
- [8-extension.md](8-extension.md): the extension port, the code review and its fix verification;
- [8-extension-browser.md](8-extension-browser.md): the offline Chromium proof on both builds;
- [8-goldens.md](8-goldens.md): the desktop API documents added for the extension and the CLI.

The owner-review entries are rows 105 to 117 of `OWNER-REVIEW.md`.

## Orchestrator gate

Node 22.23.4 and Bun 1.4.4 throughout.

**On `27e4400`** (the integration branch after merging the CLI), every step exited 0:
- `check` and `test` for each ported package and its legacy sibling: `downloader-core`,
  `browser-capture`, `transcription` and `subscriptions-core`, plus `apps/cli`,
  `apps/cli-legacy` and `apps/extension`;
- `port:check`, `check`, `test` and `deps:check`;
- `build:linux` and the CLI build.

All five golden runs failed in that gate, for two reasons:
- **The extended CLI cases need an isolation namespace** that the standard golden command did
  not establish. Fixed in `c28fb74`: the harness now establishes it itself, and also masks the
  passwd home.
- **The goldens ran the stale tracked CLI bundle.** Fixed in `1093114`: the bundle built from
  the ported source is committed (owner-review row 116).

**On `c28fb74`:** `check`, `test`, `deps:check` and `port:check` each exited 0.

**On `1093114`:** the CLI build exited 0. Five golden runs on the packaged offline build, with
the transcription models and real Chromium required, each compared 505 documents with 0
failures. No golden file changed.

**On `8fe1842`** (after merging `main` at `a3b3b38`, the AI permission policy fix; the only
conflict was the root test list, and both sides were kept): `check`, `test`, `port:check`,
`deps:check`, the packaged build and the CLI build each exited 0, and five golden runs with the
transcription models each compared 505 documents with 0 failures. Three more golden runs passed
without models against the host's newer Chromium.

The host was upgraded on 2026-11-21, after the first gate: Chromium 157.0.8103.79 to 158.0.8127.36
and ffmpeg 9.0.2 to 9.1. The real-browser characterization is pinned to the older pair, so `test`
(with `VIDBEE_REQUIRE_REAL_BROWSER=1`) ran with those two programs bound over the new ones in a
private mount namespace. Without that, the suites refuse Chromium 158 by version, and ffmpeg 9.1
rejects the recorder's `-thread_queue_size` input argument (owner-review row 77).

**Hosted-CI layout:** the root tests were also run with Node reachable only under `/opt` and
`CI=true`, as on hosted CI; see the pull request.
