# Phase 5 report: `downloader-core`

Phase 5 of the [Effect v4 port plan](../PLAN.md) rewrites the downloader on Effect, with its old API kept for unported consumers under the [reviewed design](../design/downloader-core.md).
The characterization inventory, process differences, export dispositions and verification receipts are in [5-details.md](5-details.md).

## Progress

- [x] Design reviewed twice independently: 15 findings, all resolved
- [x] Old downloader characterized: 238 new cases before the port
- [x] Effect implementation, compatibility package and consumer imports switched
- [x] Core metadata and playlist methods ported; one characterization case rewritten to the declared change
- [x] Gate, packaged build, golden suite (379 cases, five runs on the final build), hand exercise
- [x] Independent code review: three rounds and a final pass, 30 confirmed findings resolved
- [ ] Pull request, CI, merge, install

## What makes this phase different

The phase produces **two packages**:

- **`packages/downloader-core`**: schemas, services, pure helpers and Effect implementations for metadata, playlist admission, executors, mapping, inspection and persistence. Its suite has 101 tests in 15 files.
- **`packages/downloader-core-legacy`**: the old classes, callbacks, synchronous host defaults and Promise signatures over the new implementation, with direct Node process/file adapters and the live zod schemas still parsed by unported callers. Its Vitest suite has 374 tests in 20 files; the Node-specific suites run under the pinned Node. Seventeen consumer source/test files change imports, plus the desktop bundler configuration.

An in-package `legacy/` directory would still face the strict rules; the sibling keeps synchronous Node operations, callback delivery, original errors and live zod values without suppressions in the ported unit. Dependencies point from compatibility to native. The sibling shrinks as callers migrate and is removed in phase 10.

`DownloadProcess` accepts an explicit command specification and an Effect sink. Compatibility listeners enter that sink synchronously before returning to Node; asynchronous verification starts at the original continuation point in an owned scope. Raw completion retains nullable exit code, signal and actual Node killed state. The stock native spawner instead supplies numeric exit or `PlatformError`, asynchronous acquisition and stream delivery, with its own cleanup and chunk boundaries. The application keeps the compatibility process backend; phase 9.1 must remove or declare those differences before switching it.

## How parity was established

1. **Characterization first.** Before the port, 155 Bun-hosted Vitest cases and 83 pinned-Node cases were added against unchanged source. They pin exact argv, callback state at emission, Promise settlement, inventory writes, discovery, admission, cancellation and malformed inputs. Each added set passed ten consecutive runs. The existing suites moved to the compatibility package; only the declared wrong-scalars case changes its assertions.
2. **Node and wrapper oracles.** Node-specific fixtures find the pinned Node 22.23.4 executable by scanning PATH and verify it, including grandchildren; the earlier machine-specific fallback was removed. Real Node children and controlled raw observations pin missing executables, signals, abort, descendant-held pipes and exact errors. Installed-wrapper comparisons additionally check emulation over the same raw observations. Separate native tests cover acquisition, stream failures, cancellation and stock cleanup; a two-runtime test checks synchronous downloader/queue re-entry with finish persistence suspended.
3. **Packaged goldens.** The unchanged suite includes the 21 loopback download cases recorded before both ports: bundled yt-dlp/FFmpeg, success, remux, errors, observed-body cancellation, retry, batch and persisted restart. It passed on the build of every review round and five consecutive times on the final build. No golden changed.

## Declared changes

One behavior change, design section 9.1: mapped Core metadata that cannot inhabit the public model now fails with native `BoundaryDecodeError`; compatibility reports `Error("Invalid yt-dlp metadata.")`.

The measured cases are numeric `id`, boolean `title`, infinite `duration` or `view_count`, numeric `format_id`, boolean `ext`, and infinite format `height`. The combined wrong-scalars characterization previously returned ID `7`, title `false` and duration `Infinity`; that one case now expects rejection and keeps its former assertions in `// Before the port:` comments.

Primitive roots and format entries that map to valid defaults remain accepted. Ignored or trimmed optional fields retain their normalization. Null roots and non-array `formats` retain their original TypeErrors; compatibility reconstructs original JSON parser exceptions. Strict public schemas now preserve the old zod defaults, constraints, decoded URL normalization and unknown-key stripping; native in-process models remain distinct. Inventory key stripping, BOM rejection and Redgifs null traversal are preserved. Native process timing differences are phase-9.1 obligations, not declared application changes here.

## Independent code review

Independent reviewer sessions examined the diff, one per concern: facade parity, logic parity,
processes and resources, and the standard and test integrity. A second reviewer re-verified each
finding against old and new code. Verification passes followed each set of fixes; the three rounds
below record 27 confirmed findings and a final pass three more, all resolved. The earlier ports' separate review is recorded
in [review-fixes.md](review-fixes.md).

| Round | What was reviewed | Confirmed findings | Notable findings | Resolution |
| --- | --- | --- | --- | --- |
| 1 | Implementation, facade, processes, schemas and test integrity | 3 major, 12 minor (15 total; two pairs overlap) | Generator cleanup skipped failures; native Core cancellation never signalled its child; schema defaults/validators lost; curried helpers misdispatched; retry lost parser text | [First-round findings](5-details.md#first-round-findings) |
| 2 | Fixes and the differential oracle after removing engine-error emulation | 2 major, 4 minor (6 total) | Falsy format/container fields changed argv; oracle varied whole objects instead of their fields; URL decoded values and Windows joins differed | [Second-round findings](5-details.md#second-round-findings) |
| 3 | Second-round fixes, schema boundaries and stateful services | 1 blocker, 1 major, 4 minor (6 total) | Instagram controller keys collapsed by structural equality; filename dispatch broke a valid outer-call fallback; early inventory errors waited behind scans | [Third-round findings](5-details.md#third-round-findings) |

The blocker was reachable in the application: with concurrent Instagram inspections, Effect's
structural equality treated distinct AbortControllers as one key. Cancellation silently failed
for all but the latest request and queued/running mapping state disappeared. The registry now
uses ordered records and explicit controller identity. This defect never reached an installed
build. Controlled comparisons against the old implementation cover cancelling the first or middle
request, finishing one while others remain, and an unreadable inventory while an earlier scan is held.

The review made three differential oracles permanent parts of the gate: 105 pure functions over
13,399 calls, 49 schemas over 15,708 calls (including decoded values), and 12 stateful entry points
or request forms over 3,207 calls. Of the stateful calls, 154 non-array replacements are explicitly
outside the comparison contract; 3,053 are compared. Four additional concurrency scenarios pin
ordering and cancellation. These counts are checked against the committed fixture files. Generation
uses populated seeds and per-field substitution, selected interacting pairs, argument mutations,
and boundary values; natural engine failures outside the declared types need only remain failures.
The full rules, per-area counts and limits are in [the details](5-details.md#permanent-oracles).

A fourth pass then re-ran the third round's fixes against the old code (52,488 argument-builder
calls, all 15,708 schema cases, the stateful fixture), drove the stateful services not yet
compared side by side (the social mappers for seven sites, the VSCO refresh path, Instagram
scans with cooldown and checkpoints, executor completion verification, persistence under
concurrent access) and checked the merge with the review-fixed task queue. It found no major
problem and three minor ones, fixed afterwards: `knownIds: null` threw where the old code
skipped the known-items file; the gallery executor accepted a collection summary with negative
or fractional counts that the old schema rejected; after the merge the executors classified
Retry-After dates with the native date parser where the task queue's compatibility package had
gone back to `Date.parse`. With those, the review ended: no confirmed finding is open.

The first CI run of this phase's pull request then failed on one case of the stateful oracle, which
had passed locally. Two of its 3,207 cases replace the download path with a relative string; old and
new code both pass it through `path.resolve` into the task id, so the recorded id depended on the
directory the fixture was recorded in. The harness now runs the matrix from the filesystem root and
the two entries were recorded again from the old code there; no other entry changed, and the old
code gave identical results from three different directories for every other case. This was a
defect in the oracle, not in the port.

The second CI run failed on a test from phase 3: the `db` test that applies the subscription
migrations to every combination of missing columns ran into the default five-second limit (7.1 s).
It had taken 3.3 and 4.0 s on the two previous pull requests and takes about 1.1 s locally; this
phase's suites now run beside it on the CI runner. The test has an explicit 60-second budget and
asserts what it did before.

## By hand, offline, on the packaged build

The isolated packaged MCP exercise completed a non-default `best[ext=mp4]/best` download with MKV remux, MP3 extraction through conversion, cancellation after observed response-body transfer and manual retry. FFprobe verified Matroska H.264/AAC and a separate MP3-only output. Three actual execution argv vectors matched the baseline after replacing only build/download roots and loopback ports; these were read from owned `/proc` descendants because application logs do not expose complete argv. That comparison predates the metadata completion.

On the metadata-complete build, renderer IPC `download.startPlaylistDownload` selected range 2–3 from a local HTML playlist with three videos. It returned exactly entries 2 and 3 with their original indexes and `totalCount: 2`; both completed. A separate bundled yt-dlp/FFmpeg video-to-MKV remux was cancelled through MCP while FFmpeg was alive; running became cancelled in 5 ms. The captured FFmpeg output pipes did not match the downloader's app-facing pipes. No real retained app-output-pipe condition after leader exit was produced; that condition has source/fake-process proof only.

The committed harness separately covers local-file import, batch, pause/resume and persisted restart. Every packaged launch used an isolated synthetic profile and offline namespace. Full requests, outputs and process/fd observations are kept in the run's scratch area, not committed.

## Found, not fixed (in `OWNER-REVIEW.md`)

The twelve characterization findings pin escaping synchronous resolver/settings throws; pending-settings cancellation without spawn/finish; different inventory identity checks; empty-category cache-cap bypass; duplicate Threads counts; size-zero executor success before the queue guard; output after finish; different callback throw/swallow locations; a Core listener failure leaking active state; preview admission leaking a directory; uneven wrapper conversion/chunk semantics; and malformed Core metadata. The last is the declared change above; existing null/formats TypeErrors remain.

The design additionally retains wrapper recovery bypass, child-only/no-escalation cancellation and descendant gaps, bare PID/group reuse exposure, generic mapper character-count limits and pre-abort gap, Redgifs TERM-only/null traversal, early directory/lease leaks, no-fsync inventory writes and rename residue, social get/list/recovery quirks, Instagram pending-Promise/identity/retry quirks, differing output verification and URL acceptance, YouTube/music branch shadowing, cookie-health shortcuts and the unenforced cookie inspection size cap. Direct-media audio requests still save the source container.

## Not verified

- Windows and macOS execution; platform paths and selected signal/taskkill branches have injected proof only.
- A real descendant retaining the app-facing downloader output pipe after leader exit.
- Packaged profile get/list/reopen by hand; source and fake-process tests cover those operations.
- Real sites, authentication, external-network downloads, feed refresh, AI or remote extension success.
- Successful local ASR; the golden harness reports its existing skip without models.
- Every compound callback/input/cancellation interleaving, every discovery permutation or real permission failure; permissions are injected.
- The native process backend in the application (phase 9.1 switches to it).
