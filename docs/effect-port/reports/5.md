## Surprises and disagreements with the design

No behavior was fixed. Expectations were corrected only while measuring the old code, before any
port. In particular the Core listener test initially assumed a later close would recover the task;
source inspection and the raw observation show that the exception prevented close-handler binding.
The test now pins the leaked active entry, not recovery.

1. **FFmpeg resolver throws escape `run`.** Unlike builder/binary/spawn failures, the resolver call
   is outside the executor's preflight catch. A synchronous `prepareSettings` throw also escapes
   by identity. A rejected settings Promise instead produces finish data.
2. **Cancellation before settings resolve emits neither spawn nor finish.** The pending handle
   acknowledges cancellation; resolving settings afterwards does not launch anything.
3. **Inventory identity differs.** Social loading checks body identity. Instagram loading accepts
   a body with a different `inspectionId` and profile username under a valid filename. Design
   section 10's identity requirement must preserve this difference, not add validation.
4. **Empty-category Instagram reads bypass cache capacity enforcement.** They can grow the cache
   beyond `maxCacheEntries`. A later completed scan prunes in insertion order; `get` does not
   promote an entry. Section 11's insertion-order statement alone is incomplete.
5. **Threads repeated identical asset records count twice.** Within-run aggregate replacement is
   retained; refreshing replaces the prior run rather than adding its counts again.
6. **Executor success is not queue success.** A yt-dlp zero close reports size-zero success when
   the file is missing. The queue applies its separate output-missing guard.
7. **Outputs can follow finish.** Controlled raw stdout after completion still produces std
   callbacks on both executors. Finish-once does not mean all later std events are suppressed.
   Part 2 must not add a blanket settled guard that changes these traces.
8. **Callback throw locations differ.** yt-dlp finish throws synchronously from raw close. Gallery
   finish throws inside its async finalizer and its catch/finish-once guard swallows that exception.
   Gallery std/progress and yt-dlp progress/processing/std throws escape their synchronous emission.
9. **Core listener failure leaks active state.** Its first `task-updated` listener can reject
   `createDownload` after active state changes but before completion listeners bind. A later raw
   close does not clean up that entry. Section 4's generic callback-identity rule must retain the
   catch location and this partial state.
10. **Preview admission rejection leaks a scratch directory.** Mapping's rejection cleans its
    directory; preview acquires outside its cleanup `try`. The tests remove their leaked fixture
    directories themselves after observing the behavior.
11. **Wrapper behavior is intentionally uneven.** Nonzero real close becomes formatted Error with
    null executor exit code; signal code is nullable; original raw error waits for close; a zero
    close can ignore a previously stored raw error. Event data retains its leading space. Split
    wrapper progress lines are not reassembled; executor chunk UTF-8 can become replacement text.
12. **Malformed core metadata escapes types.** Numeric ID, boolean title and Infinity duration
    currently escape; `formats: {}` and `null` produce Node TypeErrors. These are concrete old
    cases for design section 9's planned newly rejected-shape policy.

### Specification conflict: Core metadata (stopped part)

The brief says characterization assertions cannot change and directs the implementer to stop an
affected part when the specified mechanism cannot pass them. Design section 9 requires wrong-shaped
Core metadata and non-finite numbers to fail with `Error("Invalid yt-dlp metadata.")`. However,
`downloader-core-legacy/test/characterization-core.node.ts`'s `wrong-scalars` case asserts that
`id: 7`, `title: false` and `duration: Infinity` are returned, and separately compares that result
to the recorded old shape. It also requires exact old TypeErrors for null metadata and non-array
formats. The frozen public declaration says `id` and `title` are strings, and the strict model
uses `S.Finite`. Accepting that object as the native model would evade the required boundary codec;
rejecting it in the facade fails an assertion the brief prohibits editing.

Consequently Core metadata and the dependent playlist-metadata/playlist orchestration methods
remain in the compatibility class, preserving their original implementation and tests. The native
`Downloader` service implements initialize, create/cancel, lists/status and history removal, over
its own state, process sink and host capabilities. It deliberately does not claim a native
metadata or playlist implementation. No assertion was rewritten to conceal this conflict. The
orchestrator must reconcile the two requirements before declaring phase 5 complete.

The Core state port separately preserves the characterized EventEmitter-listener defect: a
listener throwing during the initial downloading update rejects creation by original identity
after publishing active state, before completion binding. A subsequent close leaves that entry
active. The native test pins that behavior as well as terminal event order, path extraction,
clones, cancellation acknowledgement and acquisition-failure cleanup. No bug fix was added.

### Contract spelling required by the strict rules

The design's zero-argument `ProcessSink.abort: () => Effect<void>` conflicts with strict diagnostic
`TS377091` (`lazyEffect`). The implemented capability is `abort: Effect<void>`. Its execution and
synchronous host boundary are unchanged; callers supply the Effect value and the process layer
runs it at the prescribed cancellation point. No diagnostic was lowered or suppressed.

`buildVideoFormatPreference({ oneClickQuality: "best" })` produced `height<=null`. The strict

selector/order checks for all five quality presets and the default. No golden changed. A follow-up
audit also found optional false cookie flags being mistaken for true; the original booleans and
expiration semantics were restored and covered by a complete cookie flag matrix.

### Native process cutover handoff for phase 9.1

The application continues using direct Node compatibility adapters. Native tests establish
result-level behavior; phase 9.1 must resolve or explicitly declare these event-level differences:

| Native difference | Phase-5 result and test boundary |
| --- | --- |
| Asynchronous acquisition/delivery | The stock spawner waits for spawn; compatibility starts immediately and enters sinks before Node listeners return. |
| Acquisition failure has no child | Native returns `NativeSpawnFailure`/PlatformError, with no PID or spawn event; compatibility retains spawn `-1`, error and close. |
| Exit precedes pipe drain | Native emits `nativeExit` independently, then completion after draining; tests retain descendant-held pipes until the appropriate request. |
| Raw signal/killed/error observations unavailable | Numeric exit or actual PlatformError only; no invented raw signal or killed flag. Cancellation wins only at the defined checkpoints. |
| Automatic nonzero cleanup | Real stock-spawner tests close descendants after a nonzero leader; compatibility tests retain them until site cancellation. |
| Scope-finalizer cleanup | Each native attempt owns its scope through completion; closing it invokes stock cleanup. Compatibility adds no new cleanup. |
| Detached/window defaults | Specifications explicitly set both, preserving per-site options. |
| Output rechunking | Stock streams may combine chunks; compatibility retains original chunks and per-chunk decoding. Wrapper regex splitting and UTF-8 expectations remain distinct. |
| Non-waiting control | Separate `ProcessRequests` beside `ProcessControl` preserves existing queue `kill`; PID/group/tree acknowledgements and Windows flags have focused tests. |

Real native executor matrices cover both yt-dlp/gallery zero/nonzero/signal/acquisition/pre-abort,
post-stat cancellation, descendants after leader exit, cancellation racing nonzero and TERM-ignore.
Injected native stream failures retain PlatformError messages and finish once. Six pinned-Node
installed-wrapper/emulation comparisons cover missing/pre-abort/abort-in-progress/abort-in-std,

callbacks while finish persistence is held. The original synchronous/raw suites still run through

A further failure-identity probe found that the shared downloader mapper reconstructed an Error

field from an absent one, preserving undefined as well as null, strings, objects and Error identity.
