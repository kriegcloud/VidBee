## Surprises and disagreements with the design

- Synchronous primary DRM completion starts capture, then the primary return overwrites the active
  capture handle; subsequent cancel/pause calls reach primary. This agrees with design section 11.
- A parsed log event arriving on stderr is delivered as stdout. Split JSON and UTF-8 are not carried
  across chunks. This agrees with the reviewed design.
- Positive/negative infinite transfer totals reach progress and executor callbacks, then fail only
  after body writing. Negative infinity produces negative-zero percent. This agrees with decision 12.9.
- The original profile tests assumed the requested chat was first in `list()`. Six tests failed even
  when the original file ran alone. `list()` follows directory enumeration; creator metadata can be
  first. Two assertions now select list membership while preserving the complete expected chat
  identity (and gallery route). Production source and media assertions are unchanged. One `it.each` assertion accounts for five failures; the other accounts for one.
- Availability accepts first-line `which` stdout even with a nonzero exit status, and checks neither
  ffmpeg nor Widevine. Preferred non-Chromium browsers remain accepted.

- Quality pinning chooses the first video while duration matching selects the second for clock and placement. Real DOM snapshots pin both choices.
- A 160×120 virtual screen is insufficient for Chromium's minimum rendered video box: observed origin `(0,87)` and 960×720 placement made recorder ffmpeg fail while the sidecar continued until its final missing-file stat. The browser fixture now uses a 1024×1024 virtual screen; no production behavior changed.
- Chromium fails with a UNIX socket path-length error when its temporary root is too long. Real browser fixtures create fresh short `/tmp/vbc-*` or `/tmp/vbp-*` directories and set isolated HOME/config/cache. They never use an existing browser profile.

- Design section 1's final paragraph says “Current main still exposes zod values from downloader-core.” That prerequisite description is stale after the merged phase 5: this tree already imports the retained OnlyFans zod schemas from `downloader-core-legacy`, while strict downloader-core supplies the models. The design amendments take precedence; part 2 must use the merged contracts. No executing-behavior disagreement was observed.

### Native cutover obligations and implementation limit

The application still uses compatibility capabilities. Phase 9.1 must explicitly resolve native
acquisition timing, stock intermediate output buffering/rechunking, unread pipes, unavoidable child
error observation, numeric exit versus raw close/signal/killed values, late-close observation,
owned-scope cleanup and process/timer liveness before switching it. No raw observation is invented
for native acquisition. Native stdin is an attempt-owned open feeder: repeated writes preserve
stdin and a real 4-MiB backpressure case acknowledges before the child drains it.

Two representation details were required to preserve existing characterization without changing
its assertions: optional raw invocation projections retain omitted Node spawn-option keys/string
stdio and recorder's string `q` write, and optional on-demand observer activation retains sidecar's
spawn/attach/public-onSpawn/abort/data/error/close registration order. Default downloader invocation
and observation behavior remains unchanged. Raw liveness reads child exit/signal properties without
adding an exit listener; native liveness uses the stock handle. These are host-boundary details,
not a second process/orchestration implementation.

**Native unreferenced timers are incomplete.** Effect 4.1.4's public Clock/Effect/Scheduler path has
no unref or keepAlive option; a direct timer attempt produces TS377073 (`globalTimersInEffect`).
No alias, suppression or replacement host mechanism was introduced. Compatibility implements the
old false/unref behavior; native true/reference behavior is tested. Native false returns an
explicit schema-backed unavailable failure. This does not satisfy the design's native false
verification requirement, and the phase cannot be called fully complete on that basis.
