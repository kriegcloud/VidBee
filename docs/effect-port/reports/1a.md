# Phase 1a report: toolchain and pilot (`logger`)

Phase 1a of the [Effect v4 port plan](../PLAN.md). It installs the Effect v4 toolchain, creates
`@vidbee/schema`, writes the ratchet checker and ports the smallest package, `logger`, as the worked
example. The app's behavior does not change. How to port a package from here on is in
[PORT-GUIDE.md](../PORT-GUIDE.md).

## What was built

**Catalog.** Added at beep-effect's pins (reference commit `65bdb9c9`): `effect`,
`@effect/platform-node`, `@effect/vitest` 4.1.4, `@effect/tsgo` 0.70.0, `tsrs`
0.25.0-ts7.1.0-beta, `lefthook` ^2.2.2, `turbo` ^2.11.11; `vitest` moved to ^5.1.0 and
`@biomejs/biome` to 2.5.6 (from 2.5.15, to match the reference). `prepare` runs
`effect-tsgo unpatch --tsrs && effect-tsgo patch --tsrs && lefthook install --force`.

**`tsconfig.base.json`.** Copied from the reference. The only change is `@vidbee/*` in place of
`@beep/*` in `namespaceImportPackages` (and in the comment that mentions it). Every compiler
option and every severity is the reference's; `overrides` is empty.

The plan says the rule set has 187 diagnostics, all `error`. The reference file today, at tsgo
0.70, has **150 entries: 145 `error` and 5 `off`** (`apiStabilityLeak`, `experimentalApiUsage`,
`preferBarrelImport`, `preferNamespaceImport`, `unstableApiUsage`). The copy keeps the reference
exactly; nothing was lowered. Recorded in `OWNER-REVIEW.md`.

**Lint.** `ultracite` and `husky` are gone. `biome.jsonc` is the reference config without its
private Grit plugins, paths and overrides, and includes only ported packages. Unported code is
checked by `biome.legacy.jsonc`, which extends the two ultracite 8.0.2 presets vendored under
`standards/biome-legacy/` (phase 10 deletes them). The legacy lint reports the same result before
and after: 567 files, 1 warning, no reformatting of unported source.

**Hooks.** `lefthook.yml` replaces `.husky/`. The pre-commit hook runs Biome on the staged files of
ported packages and `bun run port:check`. Both are read-only: nothing stashes, formats or stages,
so the hook no longer breaks merge commits.

**Turbo.** Cached per-package `check`, `test` and `build`. `tsconfig.base.json`, `biome.jsonc` and
the allowlist are global inputs. Ported packages have beep-shaped scripts: `check` is
`tsrs -p tsconfig.json --emitDeclarationOnly && tsrs -p tsconfig.test.json && biome check .`,
`test` is `bunx --bun vitest run`.

**`@vidbee/schema`.** `LiteralKit` (four source files and its test) copied from the reference.
Its `@beep/utils` imports became the public `effect/Array` and `effect/Record` modules, and the
`@beep/identity` call became explicit schema identifiers, so no further helper was copied. The
reference test asserted two invalid calls with `@ts-expect-error`; here those five rejected calls
are checked by a compiler fixture (`scripts/schema-types.test.mjs`) so the source has no
suppression comment. 42 tests pass.

**`bun run port:check`** (`scripts/port-check.mjs`, `--json` for machines). It lists every
tsconfig under `apps/` and `packages/` as ported or unported (17 today, 4 ported), and in ported
units fails on:

| Rule | What it rejects | Allowed in |
| --- | --- | --- |
| `diagnostics` | `@effect-diagnostics` comments | nowhere |
| `overrides` | a non-empty tsgo `overrides` in `tsconfig.base.json` | nowhere |
| `promise` | `Effect.promise`, `Effect.tryPromise` | `*.driver.ts` |
| `runtime` | `Effect.run*`, `ManagedRuntime` | `legacy/`, entry points (`index`, `main`, `entry`, `cli`, `*.entry`) |
| `suppression` | `@ts-ignore`, `@ts-expect-error`, `@ts-nocheck`, `biome-ignore`, `eslint-disable` | nowhere |
| `native-collection` | `new Map`, `new Set` | nowhere |
| `node-http` | imports of `node:http`, `node:https` | nowhere |
| `zod` | imports of `zod` | nowhere |

The plan asks for the first four. The last four are the owner's standing rules and the
no-suppression rule from plan section 5, added so the ratchet enforces them instead of a reviewer.
The only way around a rule is an entry in `standards/effect-allowlist.jsonc` (file, rule, reason;
empty today). A self-test (`scripts/port-check.test.mjs`) proves each rule fires and that an
allowlist entry exempts exactly one file and rule.

**`logger`.**

- `Logger.model.ts`: `LogLevel` (a `LiteralKit`), `LoggerOptions`, `CaughtErrorEvent`.
- `Logger.service.ts`: `NodeSink` and `ClientSink`, the `Context.Service` contracts for where log
  lines go.
- `Logger.layer.ts`: Effect `Logger` layers that forward to a sink. `Fatal` maps to `error`,
  `Trace` to `debug`; a non-empty `Cause` is appended as a structured detail.
- `Node.driver.ts`, `Client.driver.ts`: the only files that call evlog.
- `@vidbee/logger` and `@vidbee/logger/client` now export only the Effect API. Ported code logs
  with `Effect.log*` under one of the exported layers.
- Legacy facade: `@vidbee/logger/legacy` (`initVidbeeLogger`, `logCaughtError`, `createLogger`,
  `createRequestLogger`, `log`) and `@vidbee/logger/legacy/client` (`logger`, `log`) keep the old
  signatures and output, each on one module-level `ManagedRuntime`. The browser facade still calls
  `initLog` on import. `logCaughtError` gained a data-last overload because a reference diagnostic
  requires it; the `(event, error)` form is unchanged.
- Consumers switched (8 imports): desktop `main/config/logger-config.ts`, `preload/index.ts`,
  `renderer/src/lib/logger.ts`, and five files in `packages/task-queue`.
- `src/script.mjs` (used by the JavaScript build scripts) is byte-identical (decision D7).
- 7 tests: all six Effect levels reach the sink in both environments, the caught-error event
  decodes, and the facade produces the same sink calls as the old code for every argument shape,
  including repeated `initVidbeeLogger` calls reading `NODE_ENV` live.

## The gate

From the repository root, after `bun install`:

```sh
bun run check        # legacy lint + locales + desktop typecheck, tsrs + Biome for ported packages, port:check
bun run test         # 216 legacy node:test tests, vitest suites of ported packages, checker self-tests
bun run deps:check   # syncpack
bun run port:check
bun run build:linux  # then the packaged offline launch
```

| Check | Result |
| --- | --- |
| `bun run check` | exit 0; legacy lint 567 files, 1 pre-existing warning; `@vidbee/schema` and `@vidbee/logger` `tsrs` and Biome clean; 4 ported configs, 0 violations |
| `bun run test` | exit 0; 216/216 legacy, schema 42/42, logger 7/7, checker and type fixtures 2/2 |
| `bun run deps:check` | exit 0 |
| `bun run port:check` | exit 0 |
| `bun run build:linux` | exit 0 |

**Toolchain proof.** A deliberate violation in a ported package made
`tsrs -p packages/schema/tsconfig.json --emitDeclarationOnly` exit 2 with
`TS377017 effect(unnecessaryEffectGen)` and `TS377162 effect(effectSucceedWithUndefined)`; after
removing it the same command exits 0. The vitest suites run under Bun (`bunx --bun vitest run`).

**Packaged offline launch** (loopback-only namespace, throwaway profile, scratch descriptors): all
eight boot lines present (database, ffmpeg, yt-dlp kernel, task queue, extension API, descriptor,
MCP with 50 tools, subscriptions lease); log lines still come out through evlog in the old format;
`get_app_status` answers over MCP; the five main routes render with no console error. The owner's
descriptors were unchanged (checksums before and after).

**CI.** The check job now runs `bun run test` and `bun run port:check`; the build and extension
jobs are unchanged.

## What in beep-effect's setup did not transfer

- The private `beep-cli` scripts (laws, JSDoc lint, docgen, `toolchain prune-tsgo-backups`).
- The private Grit plugins and repository-specific paths in `biome.jsonc`.
- `@beep/identity`, `@beep/utils` and the private test helpers; replaced with public Effect
  modules as described above.
- The "187 diagnostics, all error" figure in the plan.

## Not verified

- Windows and macOS.
- Turbo's cache was exercised locally only (second `bun run check` is fully cached).
- The renderer's logger facade was exercised by loading the five routes, not by forcing a
  renderer error through it.
