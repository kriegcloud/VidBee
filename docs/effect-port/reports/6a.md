### SQL and persisted data

Synthetic real better-sqlite3 handles run through the supplied Drizzle object. Fixtures cover all
store/meta operations, deferred begin, nested host transaction savepoints, raw transaction
control failure, failed preparation before logger invocation, both `paramsInErrors` settings,
throwing logger identity/count, duplicate replacement/merge rollback and trigger-driven clear/CAS
rollback. Per-operation traces pin SQL before Promise return and the orphan-lookup suspension.
Real-SQL API failures pin SQLite's message in saved `lastError`, preserved previous items, inner
link-write warnings and the retained unlinked admitted task. `stop` leaves the borrowed handle
open. A private synthetic file is created with mode `0600`, reopened and integrity-checked; its
sole successful residue is the database filename.

The supplied owner copy contains **0 subscription rows, 0 item rows and 7 metadata rows**. All
seven metadata rows pass the exported physical row decoder; no invalid schema path is present.
Unknown-enum and JSON-recovery count maps are empty because there are no subscription rows.
Every row was visited and metadata mapping ran, with readonly/query-only access and unchanged
private file hashes. Real subscription/item mapping is vacuous for this copy. No data content,
identifier, URL or hash is committed. Synthetic malformed rows provide the non-vacuous checks.

Only the old supplied-Drizzle path exists at this step. The compatibility/native borrowed-client
and separate node-client matrices are implementation obligations; they are not claimed here.

### Declared-change fixtures

`store-invalid.json` preserves old successful outcomes for physically invalid rows (including

## Surprises and disagreements with the design

- The design's opening amendment wins over stale wrapper descriptions in sections 4, 8, 10 and
  11: the supplied-store boundary unwraps top-level Drizzle query errors. Callers receive the
  original `SqliteError` and SQLite message for either `paramsInErrors` setting. The supplied
  logger still observes exact SQL/parameters; arbitrary logger exceptions retain identity.
- RSS checks retain the original subscription snapshot through update/removal and are not
  aborted by remove/stop. They can replace child rows and admit after parent removal. Profile
  removal instead aborts its owned signal and suppresses later merge/admission.
- Updating platform and categories validates against the old platform and retains the existing
  source kind/profile owner. The tests keep that behavior.
- A second acquisition of a fresh locally owned lease drops local ownership without releasing
  the stored lease. A zero heartbeat handle is skipped by truthiness-based cleanup.
- A null-expiry lease looks acquirable to election but is refused by metadata CAS. An explicit
  preference can block stealing an expired lease.
- TypeScript's declared `() => void` unsubscribe actually returns the Set deletion boolean;
  duplicate and stale closures retain original callback identity.
- Bun's external-data traversal TypeError text differs from Node. Exact malformed XML recovery
  is therefore asserted in pinned Node, while Bun only pins raw parser payloads.
- The owner copy has no subscription/item rows; the audit cannot establish their real-data
  mapping beyond its vacuous count, even though synthetic coverage is complete for its fixtures.

## Surprises and disagreements with the design

1. **Schema export deletion conflicts with unchanged public-entry tests.** Design
   section 3, “Zod liveness”, deletes unused runtime schema
   exports (retaining the update closure), while section 10 and this lane brief
   require every public export entry to survive by import retargeting with no
   assertion edit. The oracle pins all twenty schema exports and their existing
   root/subpath identities. Before part 2, decide explicitly whether compatibility
   keeps all twenty exports or the design authorizes a public API deletion.
   Native Effect schema comparisons should compare acceptance and decoded values;
   zod issue representation remains a compatibility observation.
2. **The historical six standalone type errors no longer reproduce.** The unchanged
   source's `typecheck` exits 0 on this tree. No source repair was made. The scoped
   characterization config remains independent as requested.
3. **Bun and Node have different external traversal messages.** Bun appends an
   explanation to `candidate.trim is not a function`. Exact malformed XML recovery
   and persisted-error wording are pinned in the explicit Node oracle. The original
   Node TypeError is preserved, not generalized as an out-of-type engine case.
4. **Stale Drizzle wrapper prose is superseded by the design amendments.** Under
   both `paramsInErrors` settings, callers receive the original `SqliteError` and
   SQLite message. The supplied logger still observes exact SQL and parameters.
   Real-SQL API recovery persists `replacement refused`, not a Drizzle query string.
5. Preserved oddities include inherited status keys returning prototype/function
   values; unanchored URL matching and legacy Bilibili path shapes; whitespace
   preferred identities dropping items; truthy malformed title/artwork values
   surviving normalization; duplicate RSS URLs retaining distinct IDs while profile
   policy dedupes URLs; profile latest-only not trimming backlog; empty profile
   checks sampling time; and autoDownload=false retaining filtering/history calls.
6. Reacquiring a fresh locally owned lease clears local ownership without deleting
   the stored lease; null-expiry present leases are considered acquirable but fail
   CAS; preference can block an expired steal. A zero heartbeat handle is not
   cleared, while scheduler zero handles are cleared. Lease ULID time is independent
   of the injected election clock.
7. Enqueue failures can leave seen rows that suppress retries, and link-write
   failures can retain an unlinked admitted task. Inner warning-logger failure can
   become the saved feed error; outer warning-logger failure prevents that write.
   RSS checks continue after removal/stop; profile removal aborts its owned signal.
   Updates validate categories against the old platform and retain source kind/owner.
8. The requested broad rsync `--exclude dist` also omits dependency runtime files.
   The first copied-tree test failed before executing tests (`tsx` not found).
   Restoring `node_modules/` with a second rsync fixes the copy; the successful
   relocated gate uses the copied tree and its complete dependency files.
