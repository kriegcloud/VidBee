## Result and API

`@vidbee/i18n` now exposes Effect initialization through `I18nInitializer`,
`I18nInitializerLive` and `initSharedI18n`. The service key is
`@vidbee/i18n/I18n.service/I18nInitializer`. The third-party Promise boundary lives
in `I18n.driver.ts`; failures become the schema-backed `I18nInitializationError`.
The driver still takes the consuming application's React binding. It does not
import a react-i18next runtime or own a second binding instance.

`LanguageCode` is a LiteralKit; `LanguageDefinition`, `SystemProfileInput`,
`SystemProfile`, `SystemProfileHints` and the constructed `I18nOptions` have schemas. The pure helpers,
language table, list order, resources and translation type remain on their
existing entries. `./system-locale` has pure decision logic with schema-modeled injected hints;
it reads neither process.env nor Intl. Its optional `defaultLocale` hint lets a
caller supply the Intl fallback independently from the environment hints.

The bundled translation dictionary uses a recursive string/object schema. All
14 dictionaries decode in the package tests, and every translated key is checked
against English recursively. The public `TranslationDictionary` type remains
`typeof en` for existing callers that use its concrete keys. Decoding is a test
boundary for these immutable bundled assets, avoiding 14 dictionary decodes on
every application start. The existing desktop completeness checker remains
unchanged and still runs in `bun run check`; it owns missing-key validation.

## Legacy facade and consumers

`@vidbee/i18n/legacy` retains `initSharedI18n(instance, reactBinding):
Promise<I18nInstance>` through one module-level ManagedRuntime. A driver failure
is unwrapped before rejection, preserving the exact original error object,
class and message. The facade also re-exports the existing pure language exports,
`createI18nOptions`, resources and translation type. A pipeable overload was
added to satisfy the strict reference diagnostic; the original two-argument
signature remains unchanged.

`@vidbee/i18n/legacy/system-locale` retains the optional-input synchronous
`detectSystemProfile` signature and its fresh process.env/Intl defaults through
one module-level ManagedRuntime. It re-exports `languageFromTag`,
`isMainlandChineseLocale`, `SystemProfile` and `SystemProfileInput`.

## Configuration and dependencies

Both source and test configs extend the unchanged root reference matrix. The
base does not enable resolveJsonModule, so the package adds it, JSON source
includes, and import attributes required by NodeNext. The test config disables
emit/composite/incremental/declarations exactly as logger's test config does.
Package scripts match logger; root Turbo filters include i18n for check and test.
Biome includes the package but explicitly excludes `src/locales/**`. No locale
JSON file changed.

The package adds existing catalog Effect/Vitest dependencies and workspace schema,
moves i18next to runtime dependencies, and drops its unused react-i18next
runtime dependency. React bindings continue to belong to consumers; their
react-i18next dependencies and the root catalog entry remain. The lockfile change
only updates i18n's workspace dependency stanza.

## Preserved behavior (listed in OWNER-REVIEW.md)

These existing behaviors are pinned and deliberately preserved:

- Locale environment precedence is LANG, LC_ALL, LC_MESSAGES; LANG can win over
  LC_ALL even though many OS tools give LC_ALL priority.
- `normalizeLanguageCode("zh-HK")` returns `zh`, while
  `languageFromTag("zh-HK")` returns `zh-TW`.
- The primary locale includes VIDBEE_LANGUAGE. Forcing French with a Chinese host
  locale can therefore remove that host locale's China preference unless the
  timezone or country independently selects China.
- English primary locale falls through to timezone/country; the first recognized
  locale wins, so later non-English locale entries do not override that choice.
- Concurrent calls are not newly deduplicated: the old initialized-flag check is
  preserved. No concurrency behavior was changed or claimed.

An initial packaged build passed five consecutive full golden runs before final
self-review added the explicit SystemProfileHints schema. All gates, build and
five goldens passed again against that final source; the first receipts
remain under scratch `initial-proof/`. The parity test itself did not change.
