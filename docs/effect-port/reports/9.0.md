## Surprises and disagreements with the design

The environment initially had no `node_modules`, contrary to COMMON.md. The
first build exited 1 with `ERR_MODULE_NOT_FOUND` for `@vidbee/logger`. Initial
Bun install attempts exited 1 with EROFS. Setting writable install-cache and
temporary paths resolved installation; the subsequent build passed. Lifecycle
scripts were not run wholesale; the tsrs patch was applied explicitly.

The first forced-two-core focused run exceeded Vitest's existing five-second
limit because the harness retranspiled identical files for every fresh VM.
Caching transformed text, invalidated by source content, resolved this without
raising a timeout or sharing evaluation/store state. This was an assertion
timeout, not a memory-guard signal. The full root suite then passed on two cores.

The first restart repeat exposed an exact-root normalization omission: the old
app retains the previous HOME's default download path as a custom path after
profile relocation. The fixture distinguishes `<previous-home>` from `<home>`.
Only those exact roots are replaced; no general path, error, order or timestamp
rule is added. Both failing and successful receipts remain in scratch.

The timezone matrix exposed real old-code behavior: with English LANG held
fixed, fresh profiles select `en` in UTC and `ja` in Asia/Tokyo. The first Tokyo
comparison against the UTC fixture correctly failed. Separate
`packaged.tokyo.expected.json` records the Tokyo result; no language value is
normalized. Returning profiles retain their chosen language.

The typed view, duplicate-wire-key rejection, Uint8Array RPC and bounded
transport do not exist before part 2. These are the design's section-9 changes;
they must be tested separately against the retained raw legacy observations.
The old Show Home path has no capacity-failure contract. Injected menu tests pin
loss before mount, ordered live sends without awaiting navigation, loss during
absence, and an empty new-document sink. The proposed 256-entry overflow rule
belongs to the new transport.

## For OWNER-REVIEW candidates

- Preserve the observed stale whole-object rollback on overlapping save failure.
- Preserve preload removal by returned wrapper; removing the original callback leaves the listener mounted.
- Preserve malformed raw fields and unknown nested data through unrelated writes. New typed fallback must not persist repairs beyond today's constructor writes.
- Preserve legacy ArrayBuffer results while the new typed RPC uses Uint8Array.
- New RPC/typed projection/resource accounting/Effect forwarding tests remain part 2 work; this lane adds no facade or transport implementation.
- Native tray clicks, OS login/Dock integration and background visibility need a controlled display/platform exercise. Headless log observations do not prove native visibility.
- Real native dialogs need an owned display and controlled human/OS dismissal. The injected tests establish overload and Promise behavior only.
- Clipboard paste/readback needs an owned display or clipboard-driver seam; the old public bridge exposes write only. Actual disk rotation likewise requires a dedicated sink/filesystem exercise.
- Packaged portable-mode startup remains separate from the injected portable host/module proof; it needs a dedicated disposable portable root and profile-path acceptance probe.
- Linux evidence does not establish macOS/Windows launches. Real ASR needs the separate supplied-model prerequisites documented in GOLDENS.md.
