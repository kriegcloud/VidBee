normalization, subtitle limits/filtering, and invalid nonempty TTS identifiers.
The full raw document and trace are captured immediately after each failure.
Literal field cases reuse an isolated manager only after its actual reset restores

not a DOM reconciler or a native display exercise.

third pass below): fresh, controlled quit, second-instance,

old-channel error wrapping, offline icons, preload helpers, actual Settings/About
text, a named One-Click Download switch, displayed persistence after reload,
maximize/minimize/close, PNG dimensions and controlled quit.

UTC and Asia/Tokyo have separate fixtures. Fresh-install language differs in the
old package even with English LANG. That difference is retained. Source locale
inputs are explicitly injected, so an ambient `VIDBEE_LANGUAGE` cannot override
the Japanese source fixture. Launch cwd and LANG/LC_ALL/TZ are explicit; packaged
commands assert the pinned Node version.

## Surprises and disagreements with the design

The original renderer language mock lacked ESM default interop. Its failure test
caught a mock TypeError instead of the intended language-host rejection. The mock
now executes the intended language operation and the new fixture records full
error vectors and publication timing. Application behavior was not changed.

The title bar's original-callback cleanup leaves wrappers registered: two mounts
leave two listeners per channel and one event updates both. This existing behavior
is now observed through the actual component and wrapper, not inferred from the
helper alone. Actual AppLayout cleanup uses the returned wrapper and succeeds.

Portable startup changes Electron userData to `Data/UserData` even when a scratch
`--user-data-dir` was passed. The isolated portable probe records that effective
file, plus relocation from the marker. All effective paths stay under its run.

An attempted extra worker check against the outside parent's `/proc/.../ns` failed
with EACCES inside the user namespace. That attempt refused before CDP and remains
in scratch receipts. The accepted guard compares the parent's captured namespace
identities with the current, launcher and app identities, checks loopback-only
interfaces and validates the app/profile/hash; it does not bypass proc permissions.

The expanded field matrix initially crossed Vitest's existing five-second limit.
Reusing an isolated manager after its real reset avoids redundant constructor/VM
work; baseline and each literal field have separate tests, alongside normalization,
failure, portable and conversion groups. No timeout, assertion
or diagnostic was relaxed. The logger test also supplies the host Error classes
to VM contexts so real transports recognize native Error arguments instead of
formatting a foreign-realm object as an empty object. A fixed clock supplies both
a fixed instant and local calendar fields, preserving output across timezones.

The first pass's historical validation receipts remain in its own lane. They are
not counted as final second-pass proof. Current final exits and evidence are in
the second-pass HANDOFF and machine-readable validation receipts.

## For OWNER-REVIEW candidates

A new installed-store path-fallback probe exposed a harness resolution defect:
explicit `.js` imports in TypeScript were not being resolved to `.ts`. This had
reduced the fresh-locale case to a harness error. The resolver now handles those
imports, unresolved imports use a distinct harness error that cannot be recorded
as an application failure, and the fixture requires a complete fresh snapshot.
The affected source oracle was recorded again from unchanged old source; the
final source matrix and root gate are rerun after that correction. The installed
store now also covers one failed path lookup followed by owned-directory fallback,
and persistent path failure before file creation.

No application bug is fixed. Preserve raw malformed values, partial writes,
operation-specific normalization, stale whole-object rollback, title-bar wrapper
leak, ArrayBuffer compatibility, focused native parenting, pre-lock import effects,
nonfatal boot catches and reset's absent broadcast.

Electron's headless CDP endpoint rejects `Browser.getWindowForTarget` with
`-32601`. The package records that exact error and renderer focus/visibility
around minimize/close after `Page.bringToFront`. Native window-manager bounds and
restoration require an owned headed display; no native state is invented from
the invoke result alone.

Headless packaged and injected-host proof do not establish native tray/Dock/login
integration, physical clipboard paste/readback or interactive native dialog
appearance/dismissal. Those require an owned display and controlled native input.
Windows/macOS launch proof requires those platforms; their branch behavior here
uses injected hosts. Real ASR inference needs supplied local model directories.
New RPC/Atom/typed projection/resource budgets/Cause forwarding remain part 2.
The shared glob fixture executes the actual Vite-authored module with injected
raw glob results; the packaged build supplies independent bundled integration.

## Orchestrator verification of the third pass

The orchestrator's own rerun of the source suite failed on timing, not on an assertion: while the
