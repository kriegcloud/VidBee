## Surprises and disagreements with the design

The measured behavior agrees with the reviewed design's major warnings. Additional details matter to the rewrite:

- Partial visible stage can rewind while its history refuses to rewind; a valid empty separate stage file wins over nonempty embedded history.
- SQL full hydration sorts segments by start time; memory preserves input segment order. SQL consumes the prospective clock read before task idempotence; memory checks first.
- Shared tokenizer assessment can reuse a lax result when another manager requests JSON validation.
- Caller group order creates different ensure/controller keys while sharing a raw transfer. Cancelling the later controller leaves the first fetch signal unaborted; cancellation cleanup subsequently purges its publication. The first ensure rejects `model not ready after download`, the second rejects `download cancelled: minimal`, and the asset is absent.
- A raw peer publication is accepted before the current transfer's checksum, even when that transfer's bytes have the wrong digest.
- Audio already-aborted signals do not prevent conversion. The last runtime candidate can be selected after failed probing; a final cached-false candidate is not re-probed; missing forced layers can fall back to Electron.
- SIGTERM exits are restartable because code is null, while exit code zero without result is not restarted. Unterminated result lines are ignored. In-process success leaves partial singleton state populated.
- Cloud request/result persistence precedes callbacks as specified. Throwing null from the injected cloud callback is replaced by a TypeError while inspecting its code; ordinary Error/string/number/object rejections preserve identity. This qualifies section 4's Cloud/callback rows (design lines 255–256), which broadly promise callback failure identity.
- Multi-root publication failure can run twice: the first root becomes present despite failure, so installing the remaining missing spec retries publication. Cleanup exceptions replace the original write/rename failure by identity and retain the characterized staging residue.
- The reviewed design's statement that shared timing helpers are absent is historical: this starting tree already contains the phase 5 shared helpers. This is section 5, “Timing, settlement and runtime ownership” (design line 375); no extraction is needed by the rewrite.

No behavior was corrected and no design file was edited.

### Stability-discovered PID marker race

The first complete audit verification attempt passed both root timezone matrices and four package/UTC repetitions, then package/UTC repetition 5 failed in the original open-stdin pipe case: its child lookup used PID 0. This was a fixture publication race, not package behavior. `existsSync(ready)` can observe an empty inode before the child's `writeFileSync` writes PID bytes; `Number('')` is 0. A deliberately delayed write reproduced this exact condition through public `extractMonoWav`, and completing the marker found the expected owned child/stdin and completed extraction. Failed receipts and the reproduction remain scratch evidence; none count toward final stability.

`fixtures/audit-pid.ts` now requires a newline-terminated positive safe integer before a PID marker is ready. All PID-marker reads feeding liveness/signals in the process, executor, pipe, runtime and publication cases use it. Cleanup additionally checks that `/proc/<pid>/cmdline` names that case's exact temporary root before signalling, and the registered child/group cleanup remains authoritative. The failed open-stdin case now deliberately publishes an empty PID file, asserts it is not ready, and releases complete publication by a parent-written file before retaining every original stdin/result assertion. This makes the discovered race permanent deterministic coverage and prevents accidental PID-0 group signalling. The final frozen-tree validation was restarted in full after this repair.
