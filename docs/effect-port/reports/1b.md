# Phase 1b report: fixture profile and golden harness

Phase 1b of the [Effect v4 port plan](../PLAN.md). It builds the regression net for the port: a
synthetic fixture profile, a harness that drives the packaged app offline through MCP, the loopback
HTTP API, the CLI and the renderer, and 358 goldens recorded on the pre-port build. How to run and
extend it is in [GOLDENS.md](../GOLDENS.md). No application source changed.

## Fixture

`build-fixture.mjs` is the source of truth. Each suite bootstraps the real schema
on an empty profile, stops that app, copies the profile, removes bootstrap logs,
and seeds deterministic rows. Lazy transcript, prompt-run and chat DDL comes from
the app's actual schema declarations; no new dependency was added. Persisted file
references are rewritten to the final launch directory before copying the seed.

The fixture contains nine tasks (all eight initial statuses and an extra completed
audio task), history projections, one disabled subscription with three items,
a three-segment/two-speaker transcript with word timings, a completed prompt run,
a two-message AI thread with assistant thinking, settings, a local skill, silent
3.75-second WAVs, a PNG and an SRT. IDs and timestamps are invented and fixed.
Running/processing tasks recover and queued tasks dispatch on startup; the golden
answers deliberately pin their resulting failed states. The retry task's next
attempt is fixed in 2100.

Two fresh fixture builds from the same bootstrapped profile, with the same final
path root, produced byte-identical SQLite, settings JSON, WAV and PNG hashes.
Scratch receipt: `fixture-determinism.json`. Independent app bootstraps can still
create ephemeral coordination metadata; public comparison normalizes only the
explicit runtime fields below.

## Coverage

358 recorded documents: **168 MCP, 174 HTTP, 14 CLI, one renderer smoke and one
boot/final-log assertion**. `mcp--tools-list.json` records all 50 tool names,
descriptions, annotations and input schemas. A newly listed read-only tool absent
from the case inventory fails the suite.

All 22 read or conditional-read tools are exercised:

- `list_tasks`, `get_task`, `get_queue_stats`, `inspect_media_engine`,
  `list_download_history`, `get_app_status`, `get_settings`, `get_ai_settings`.
- `list_subscriptions`, `get_subscription`, `test_subscription`,
  `list_subscription_items`.
- `list_transcripts`, `get_transcript`, `export_transcript`, `manage_asr_model`.
- `list_agent_threads`, `get_agent_thread`, `get_agent_message`,
  `get_agent_events`, `get_ai_prompt_run`, `list_skill_results`.

Cases cover pagination, filters, every seeded task, unknown IDs, invalid arguments,
word inclusion, transcript ranges/search, five text export formats, styles and
groupings, conversation branches/message thinking and prompt-result slicing.
Successful results retain the full MCP envelope, including text and structured
content; error envelopes remain literal. MCP missing/bad bearer responses are
also recorded.

Offline MCP mutations and subsequent reads cover settings updates, task
rename/cancel, queue-group configuration, subscription update/removal, transcript
edit/insert/delete, conversation create/rename/delete and local-file import.
Import always queues ASR; the harness cancels and removes that child through
public tools before comparing subsequent lists. This avoids racing model/network
work instead of normalizing task state or progress. The resulting empty child
list and imported library entry are recorded.

All registered loopback route families have authentication/error coverage, with
successful offline operations where available:

| Surface | Routes / operations |
| --- | --- |
| Automation | `/automation/v1/{health,handshake,events,stats}`; POST `{add,get,list,cancel,pause,resume,retry,setMaxConcurrency,setMaxPerGroup,removeFromHistory}` |
| Subscriptions | POST `/automation/v1/subscriptions/{list,get,resolve,add,update,remove,refresh,itemsList,itemsQueue}` |
| Extension discovery | `/token`, `/video-info`, `/status` |
| Cookie bridge | `/extension/v1/{connect,wait,cookies}` |
| Overview/transcript | POST start, GET session, POST session cancellation for `/extension/v1/{overview,transcript}` |
| Chat | `/extension/v1/chat`, session state/commands, session `{events,options,model,images,export,feedback,tasks,videos,media}` |
| Protocol errors | Unknown routes/operations, wrong methods, preflight, absent origin and bad capabilities |

Automation subscription create/update/remove succeeds offline using declared feed
metadata. Extension start tokens, cookie connection/status, and chat
start/state/options/events/tasks/videos succeed offline. SSE comparisons retain
exactly the first complete frame, parsed into event and data, then cancel the
reader. Long-running streams are not left open.

The rebuilt CLI connects to the isolated descriptor with `--vidbee-no-autostart`:
version/status, task list variants, task status/logs, history, unknown command/ID,
missing ID and invalid limit/status. Exit code and parsed stdout/stderr are pinned.

Renderer smoke visits home, subscriptions, chat, settings and about, records
screenshots in scratch, rejects failed CDP commands and console errors, and runs
before deliberately malformed mutation cases. Boot lines are required and the
log is checked again after all API/CLI cases. Only two exact baseline offline
error signatures are accepted:

- `Using fallback thinking options: TypeError: fetch failed` (AI catalog fallback).
- `Failed to cache thumbnail: TypeError: fetch failed` (remote favicons).

The favicon attribution is supported by source and matching DNS timing:
`DownloadPlatformIcon` tries the fixture domain/favicon and `favicon.im`; About
cards request product favicons from `favicon.im`. Those are distinct from the
valid local fixture thumbnails. Exact URL assignment to each error is an
inference because the app omits the URL from that log line. Other `[error]` lines
fail, including errors emitted after mutations.

### Explicit gaps

- Remote download, feed-fetch/refresh, AI-generation and model-download successes
  are unavailable offline. Their validation/authentication/error paths are pinned.
- Successful extension caption extraction and AI overview generation require remote
  services. Unknown-session and invalid-input responses are pinned.
- Successful cookie long-poll delivery needs a concurrent cookie request; missing
  and bad-session answers are covered.
- Rendered PDF/PNG/video exports are not deterministic read cases. Transcript text
  exports are covered.
- Successful local ASR is optional and was not implemented or verified. `--models`
  can populate the fixture's model directory but changes model-inventory answers;
  the committed baseline is the model-free run. Supplying models alone does not
  establish transcription success. Without it, the suite prints an explicit skip.
- Account/network-only mutations and the remaining unchosen MCP mutation tools
  are not successful-flow coverage. All 50 declarations are pinned by tools/list.

## Normalization and comparison

Named rules are documented in [GOLDENS.md](../GOLDENS.md) and implemented in
`normalize.mjs`: known run/work/build/repository roots, generated ULID/UUID IDs,
generated 64-character `id` fields, credential fields/bearer strings, loopback
ports, process identity, explicitly named runtime timestamps newer than the fixed
fixture era, and elapsed/latency fields. Fixed fixture IDs/clocks, file names,
media durations/hashes, schemas, error text, array order, task state and progress
remain literal. Residual private home paths fail the recorder.

Only MCP `result.content[].text` JSON payloads are decoded; the `$jsonText`
marker retains their original wire type. Other application strings stay strings.
The comparator distinguishes arrays and objects and reports changed field paths.
Four built-in Node tests pin these properties and generated-ID aliasing.

## Regression proof

The original packaged directory was copied into scratch. The main bundle bytes
inside the copied `app.asar` were changed with same-length patches, preserving
archive layout and native unpacking. Expected goldens were never edited to induce
failure. The final harness detected both changes:

```text
FAIL mcp/get_app_status/default
$.result.structuredContent.result.version: expected "2.4.0", received undefined
$.result.structuredContent.result.versioX: expected undefined, received "2.4.0"
FAIL mcp/get_app_status/extension-connected
Compared 3 cases; 2 failures

FAIL mcp/get_task/unknown
$.result.content.0.text: expected "Task not found: golden-unknown", received "Task not known: golden-unknown"
Compared 13 cases; 1 failures
```

Both runner invocations exited 1. Scratch `regression-{field,error}.log` and
`regression-proof.json` contain complete output, exact patches and restoration
hashes. A `finally` block restored the copied archive and extracted main bundle;
the restored archive hash equals the baseline hash above. An initial generic
archive repack failed startup and was discarded; it is not regression evidence.

## Determinism, runtime and verification

Initial comparison caught missing runtime timestamp names and a real import-ASR
race. The race was removed with public cancellation/removal, without normalizing
status/progress. Review then caught four material harness weaknesses: array/object
equivalence, global JSON decoding, a late-exit success window and missing final
log inspection. All were fixed; an earlier five-pass series was superseded.

Final five-pass series, after all behavioral harness edits:

| 1 | `suite-fhghN6` | 358 | pass | 22.9 |

| 4 | `suite-Nx92H3` | 358 | pass | 23.1 |

Each run started from a fresh schema bootstrap/profile and compared the same
build. Full logs are `accepted-flake-1.log` through `accepted-flake-5.log` in the run

was 24.78 seconds (range 22.9–28.2). This series includes bounded CDP discovery/socket/command handling and the
restored tracked CLI bundle. No behavioral harness edits followed it; comparison
parses JSON independently of presentation formatting.

Lifecycle evidence (`lifecycle-proof.json`) used two synthetic executable stubs:
an immediate clean app exit was rejected with launcher status 1; terminating the
launcher returned 143 and left zero live processes in its owned group.

`node --test apps/desktop/scripts/port/golden/normalize.test.mjs` passed 4/4.
`bun run check` passed on the final implementation tree. The existing renderer hook-dependency warning is not changed by this phase.

CI adds separate AppArmor namespace-enablement and golden-comparison steps after
Linux packaging/native verification, rebuilding the CLI first. The hosted run is described under "Checked again" below.

## Checked again on the phase 1a build

After phase 1a merged, the suite was run against a build of that branch (the logger port and the
new toolchain) and against the phase 0b baseline build: 358 of 358 cases pass on both, in 24 to 26
seconds. The first comparison failed on one field, `inspect_media_engine` `ffmpegVersion`: the
ffmpeg binary is downloaded at setup time, so its build id differs from build to build. It is now
normalized to `ffmpeg version <ffmpeg-build>`; the rest of the string stays literal.

The first hosted CI run showed that the namespace setup works on GitHub's `ubuntu-24.04` runners
(with the AppArmor sysctl step) and that 357 of 358 cases match there. The one difference was
`manage_asr_model` status, which reports the host's CPU count, memory and hardware class and the
ASR tiers recommended for that hardware. Those fields are now replaced as a unit (`<machine>`,
`<machine-dependent>`); the tier catalog in the same answer stays literal.

`bun run check`, `bun run test`, `bun run deps:check` and `bun run port:check` exit 0 on this
branch rebased on phase 1a.

## For OWNER-REVIEW

The low-level automation `add` endpoint accepts `{input:{kind:"unknown"}}` without
a URL and returns HTTP 200 with a task ID. The renderer later calls `.trim()` on
that missing URL and emits a TypeError. The golden pins this acceptance, then
cancels/removes the malformed task. Renderer smoke runs first because its error
boundary retains an induced failure even after task cleanup. This behavior was
not fixed in application source, per phase scope.
