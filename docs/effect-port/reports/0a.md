# Phase 0a report: fork and removals

Phase 0a of the [Effect v4 port plan](../PLAN.md). It turns the repo into a personal hard fork and
deletes what will not be ported. It adds no Effect code and changes no behavior beyond the removals
below. Net change: 178 files, about 650 lines added and 20,600 removed; the lockfile holds about 160
fewer packages.

## What referenced a removed feature and had to change

- **Error reporting call sites.** About 26 `captureMainException` / `captureMainMessage` /
  `addMainBreadcrumb` calls in `src/main/index.ts` and 16 renderer calls
  (`captureRendererException`, `addRendererBreadcrumb`, `trackDesktopEvent` and the init hooks)
  were deleted. Every exception capture sat next to a `log.error` / `logger.error` that stays, so
  failures still reach the log file. Breadcrumbs with no log line beside them (deep link received,
  download queued, started and completed) are simply gone.
- **Renderer-hang handling** (`setupRendererErrorHandling`). The 5-second "report sustained
  unresponsiveness" timer existed only to send a Sentry message and is gone. The 15-second forced
  recovery on packaged Windows builds is unchanged.
- **Download errors.** The handler no longer classifies the error to decide whether to report it.
  `glitchTipEventId` is removed from `DownloadItem`, the history item type and `projection.ts`.
  Stored tasks that carry the field in their options still load; the field is ignored.
- **Long-task observer** in `renderer/src/main.tsx`: it only recorded breadcrumbs, so it is removed.
- **Agent run events.** `AgentRunEvent.analytics` (an ephemeral field only the analytics tracker
  read) and the `origin` parameter of `sendAgentMessage` that fed it are removed.
- **Share capture window.** `isAppWindow` no longer has to skip the analytics collector window.
- **Home page.** Lost its `appVersion` and `onOpenAbout` props, which only the update notice used.
- **MCP and agent tools.** `get_settings` no longer returns `readOnly.autoUpdate`, and
  `update_settings` no longer accepts `enableAnalytics`. This is the one visible change to the MCP
  surface; phase 1b records its goldens after it.
- **Settings file.** Existing `config.json` files keep their `autoUpdate` and `enableAnalytics`
  keys. Nothing reads them and nothing deletes them, so the file opens unchanged (assumption A1).
- **`WebAppSettingsSchema`** in `downloader-core` lost the same two fields.
- **Build config.** `electron.vite.config.ts` no longer externalizes `electron-ga4-telemetry` or
  defines the GlitchTip constants. Sourcemaps are still emitted and still stripped before packing.
- **Workflows.** `ci.yml` runs on pull requests to `main`: `bun run check` (Biome, locale check,
  typecheck), `bun run test:audit`, `bun run deps:check`, then calls `build.yml` and
  `extension-build.yml`. `build.yml` is now Linux only (`bun run build:linux` plus the packaged
  sherpa check); the Windows, macOS, signing, notarization, Microsoft Store and GlitchTip steps are
  gone. `extension-build.yml` also typechecks the extension.
- **Docs.** `README.md` gained a note that this is a personal hard fork; `AGENTS.md` rule 8,
  `CONTRIBUTING.md` and `apps/cli/README.md` no longer describe the web app, releases or npm
  publishing.

## Left in place on purpose

- **Account service** (`api.vidbee.org`, better-auth): untouched, per decision D4.
- **yt-dlp kernel updates** (`ytdlp-kernel-service.ts`, the "Update yt-dlp" row on the About page).
  This updates the download engine, not the app, and the vendored build already refuses to fetch
  official updates (`test/vendored-runtime.test.ts`).
- **"What's new" dialog** and `lastSeenWhatsNew`: not an updater, it only shows release notes once.
- **Links to upstream** on the About page and in the README body (repository, website, changelog,
  feedback): they are content, not ties the app depends on.
- **Windows and macOS build configuration** (`build:win`, `build:mac`, `electron-builder.store.yml`,
  the portable-folder script): kept so those platforms still build (decision D2); only CI stopped
  building them.
- **Schemas the deleted oRPC contracts consumed.** 41 exported zod schemas in
  `downloader-core/src/schemas.ts` (plus `FanslyProfileSchema`), 10 in `subscriptions-core` and 9
  in `task-queue` now have no consumer. They are left for each package's port phase to delete,
  where the schema file is rewritten anyway.
- **`.agents/skills/orpc-contract-first`**: an agent skill about oRPC that no longer applies.
- **Stale comments** that still name `apps/api` or a Sentry issue id as history.

## Surprises

- **Upstream had nothing new.** Step 1 produced no merge commit.
- **The CI workflows had never run on the fork**, so the first run found two environment problems,
  both fixed on the branch: the pinned gallery-dl standalone binary needs glibc 2.38 and failed its
  version check on `ubuntu-22.04` (the jobs now use `ubuntu-24.04`), and `upload-artifact` skipped
  the extension zip because `.output` is a dot-directory (`include-hidden-files: true`).
- **Stale `node_modules` in the main checkout.** Per-package `node_modules` directories left over
  from pnpm made `bun install --frozen-lockfile` fail in the extension's `postinstall` (a dangling
  `wxt` link). Removing those untracked directories fixed it; nothing in the repo changed.
- **Many schemas existed only for the web API.** Deleting the oRPC contracts orphaned about 60
  exported zod schemas across three packages (listed under "Left in place on purpose").
- **The updater was already inert here.** Builds with the vendored yt-dlp skipped
  `initAutoUpdater`, so on the owner's machine the visible change is in the UI and the settings,
  not in network behavior. Telemetry was live: the previous build still looked up
  `www.googletagmanager.com` at startup.

## Not verified

- **Windows and macOS.** Nothing was built or launched there (decision D2). The removals touch
  shared code only, plus one line of the Windows portable-folder script.
- **The removed UI by eye.** The About, Settings and Home screens were not screenshotted. They
  typecheck, the renderer bundle builds, and the packaged app loads its renderer without errors,
  but nobody has looked at the About page without its update row.
- **A populated profile.** The gate launch used an empty profile. Opening the owner's real database
  with this build happens at the first real start after install.
- **A real download.** The launch was offline, so no download, subscription refresh or account
  sign-in was exercised.
- **`apps/cli` and `subscriptions-core` standalone typechecks.** They fail on `main` too (41 and 6
  errors, mostly `packages/downloader-core/src/dzen-profile.ts` strictness errors reached through
  the CLI's stricter tsconfig). The errors are byte-identical before and after this phase, and
  neither is part of `bun run check`. They are left for the package port phases.
- **Chromium's own network use.** `redirector.gvt1.com` is Electron's bundled Chromium component
  updater. It is not VidBee code and this phase does not disable it.
