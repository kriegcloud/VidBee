## Fixes the updates needed

- **`@types/node` 26.** `path.PlatformPath` no longer exists (`cookie-browser-paths.ts` now uses
  `typeof path.posix`), and the global `setTimeout` type no longer fits the injectable scheduler in
  `transcription/src/init-models.ts` (the default is now a wrapper with the option's own type).
- **i18next 27.** `t` is typed as a union of argument tuples that rejects a function type with an
  optional second parameter. Twenty call sites that pass `t` to a label helper now pass
  `plainTranslate(t)` (`renderer/src/lib/plain-translate.ts`), an adapter cached per `t` so hook
  dependency arrays see a stable identity. `packages/ui` `download-container-select.tsx` widens a
  generic template-literal key to `string`.

- **wxt 0.21.** Its generated tsconfig turns on `noUncheckedIndexedAccess`, which flagged two
  expressions in the extension popup (`tab.url` after the URL guard, `groups[h]`). Both now handle
  `undefined` explicitly without changing what runs. CI caught this; locally the generated
  `.wxt/tsconfig.json` was stale until `wxt prepare` ran again.

No other source changed. `apps/desktop/src/main` is untouched.

**Packaged offline launch** (loopback-only namespace, throwaway profile, scratch descriptors). Boot
lines: database initialized, 14 IPC services, ffmpeg initialized, yt-dlp kernel activated,
task queue started with 0 tasks, extension API on 127.0.0.1:27100, descriptor written to scratch,
desktop MCP with 50 tools, subscriptions lease acquired. The only warnings are the offline ones
(model download retries, GPU probe disabled by `--disable-gpu`, protocol handler registration).
Hosts resolved: the same set as the 0a build (model mirrors and Chromium's component updater).

**Renderer.** `cdp-shots.mjs` visited Home, Subscriptions, Chat, Settings and About. Every route
rendered translated text and none logged a console error or an uncaught exception, which covers the
i18next, react-i18next, Jotai, framer-motion and lucide updates at runtime.

**Transcription on sherpa-onnx 2.0.1.** The native module took a major version, so it was exercised
end to end: the minimal model set (VAD, speaker, Whisper tiny, copied into the scratch profile) was
reported ready by `manage_asr_model`, a sample WAV was imported with `import_media`,
`start_transcription` ran, and `get_transcript` returned one segment, 0 to 6625 ms, with the
expected sentence and one diarized speaker.

The owner's descriptors were not touched: the checksums of `~/.config/VidBee/automation.json` and
`mcp.json` were identical before and after the launches.

## Found, not fixed

- On a fresh profile the log shows `Video library backfill failed: SqliteError: no such table:
  transcript_prompt_runs` about 25 seconds after the first import. `video-library-host.ts` reads the
  table before `ai-prompt-store.ts` has created it. It is a warning, the import and transcription
  succeed, and this phase did not touch that code.
